## 1. ホスト名（最優先。後から変更できない）

QRコードに `{HOST_URL}/i/0042` が埋め込まれる。**ラベルを印刷して貼った後は変更できない。**

- **短いホスト名を割り当ててほしい。** URLが長いほどQRの模様が細かくなり、
  本の背表紙や機器の隙間のような小さい場所に貼れなくなる
- そのホスト名が**数年変わらない見込みか**を確認したい
- `http` / `https` もURLの一部になるため、2とセットで確定する

> **現在 k3s に載っている `equipment-management.home.arpa` は仮のURL。**
> `deploy/k3s/README.md` にも「永久ラベルへ印刷するURLではない」と明記されている。
> **これを印刷してはいけない。**

## 2. HTTPS を用意できるか

`COOKIE_SECURE` の値がこれで決まる。**HTTPS でないのに `true` にすると、
Secure Cookie がブラウザに保存されず、ログインが無限ループする。**

- 証明書の**取得と更新をどちらが担当するか**。期限切れで全員がログインできなくなる
- Traefik で終端するか、Cloudflare Tunnel 等を入れるか（現在は未導入）
- **HTTP のまま運用する場合は、パスワードが平文で流れることの合意を明示的に取る。**
  学内LAN限定・tailnet 限定であっても同じ

## 3. 学外からのアクセス

- 現在は**各自の Tailscale subnet router から LAN に入り、Traefik を経由**する形
- これで「学外から使えるか」は解決しているが、**部員全員が subnet router を
  設定できるか**という問題に形が変わっただけ。設定できない人が出ると、
  その人の記録は残らない
- 影響する機能: 事後登録（持ち出した後に自宅から記録する）、M3 の通知リンク

## 4. 電源とマシンの復帰

k3s の Pod は自動で再起動するが、**それはノードとk3sが動いていることが前提。**

- OS 起動時に **k3s が自動起動する**設定
- 停電復帰時に**マシン本体が自動で電源投入される**設定（BIOS）
- UPS の有無。SQLite は WAL だが、書き込み中の電断が無害というわけではない

## 5. バックアップ

**`reclaimPolicy: Retain` はバックアップではない。** PV が載っているディスクが
壊れれば一緒に消える。

- **実行主体と保管場所を決める。** アプリは `-backup` サブコマンドを持ち、
  稼働中でも一貫したコピーを取れる（`VACUUM INTO`）
- **別の機器へ退避する。** 同じマシン上の控えは、マシンごと壊れた時に一緒に失われる
- **写真（`/uploads`）は `-backup` に含まれない。** DBだけ戻しても写真は戻らない
- 世代管理（何世代・何日分）
- **ディスクの空き容量の監視。** 尽きると SQLite が書けなくなり、
  **記録が静かに失われる**
- 復元（`-restore`）は**サービス停止が前提**。止めてよい時間帯の合意が要る

## 6. 時刻同期

- **NTP が効いていること。** 時計がずれると借用日時と返却期限の判定がずれる
- タイムゾーンはアプリ側で完結している（+9時間固定）。OS の tzdata は不要

## 7. SMTP

無くても動く。無い場合に効かなくなるもの:

- 代理登録された本人への通知（**誤登録に本人が気づけなくなる**）
- M3 の月次通知・期限超過通知

確認したいこと:

- 学内リレーの有無とホスト名
- ポート（**587 が使えるか。25 は多くの環境で塞がれている**）
- 認証の要否と認証情報
- 送信元に使えるアドレス（`noreply@…` を想定）
- 送信数の制限

**使えない場合は代替（Slack / LINE）を決める必要がある。**

## 8. ネットワーク

- アプリは 8080 で待ち受け、Traefik が前段に立つ
- 学内ファイアウォールでの許可申請が必要かどうか

## 9. 運用アクセス権と引き継ぎ

- 管理者アカウントの作成・バックアップ・復元は、**`kubectl exec` 越しにアプリの
  サブコマンドを呼ぶ**形になる。誰がこれを実行できる状態にするか
- **その権限を次の代へどう引き継ぐか**（数年で担当が全入れ替えする前提）
- `SESSION_SECRET` を誰が生成し、どこに保管するか（Secret に入れる。`.env` はコミットしない）

## 10. 監視

- 死活確認は `/healthz`。k3s のプローブ3種（startup / readiness / liveness）は設定済み
- **ただし異常になっても誰にも通知が飛ばない**
- 外形監視を置くか。置く場合、**誰に通知が届くようにするか**

---

## 用意してもらう必要が「ない」もの

余計な作業を依頼しないために明示しておく。

- **DBサーバ** — SQLite がバイナリに同居している
- **言語ランタイム** — コンテナイメージだけで動く（scratch ベース、26MB程度）
- **`sqlite3` コマンドやシェル** — 本番イメージに入っていない。
  運用操作はすべてアプリ自身のサブコマンドが持っている
