# M1 実装依頼書：基盤 + 備品マスタ + QR発行

## 0. このドキュメントの使い方

これ単体で実装に着手できるように書いてある。`requirements.md`（要件定義）と `url-design.md`（URL設計）、`schema.sql`（DDL）が前提資料。

**M1 の完了条件は「棚卸しCSVを取り込み、QRラベルを印刷して貼れる状態になること」。** 貸出機能は M2 なので、ここでは実装しない。

---

## 1. スコープ

### 実装する
- マジックリンク認証、セッション管理
- ロール制御（admin / member）
- 備品マスタ CRUD（admin のみ）
- 備品一覧・検索・詳細（member 閲覧可）
- CSV一括インポート（コード自動採番）
- 管理画面からの1件ずつ登録（スマホ対応、写真添付）
- QRコード発行、ラベル一括印刷（PDF）

### 実装しない（M2以降）
貸出・返却、所在不明報告、通知、棚卸しモード、公開API。
**これらのUIへの導線も置かない。** 押せないボタンは混乱のもとになる。

## 2. 技術スタック

| 領域 | 選定 | 理由 |
|---|---|---|
| バックエンド | Go 1.22+ | |
| ルーティング | **標準 `net/http` の `http.ServeMux`** | Go 1.22 からパスパラメータを扱える。フレームワークを入れない |
| DB | SQLite | |
| DBドライバ | **`modernc.org/sqlite`** | cgo 不要。`mattn/go-sqlite3` は cgo 必須で Docker のマルチステージビルドが面倒になる |
| マイグレーション | `embed` + 連番SQLファイルの自作ランナー | 依存を増やさない。規模的に十分 |
| フロントエンド | React + TypeScript + Vite | |
| ルーティング | React Router | |
| スタイル | Tailwind CSS | |
| QR生成 | `github.com/skip2/go-qrcode` | |
| PDF生成 | `github.com/go-pdf/fpdf` | `jung-kurt/gofpdf` はメンテ終了 |
| パスワードハッシュ | `golang.org/x/crypto/bcrypt` | 標準ライブラリに無い。自作すると必ず間違える箇所 |
| メール送信 | 標準 `net/smtp`（接続先は環境変数） | **M1では使わない**（認証がメール非依存になったため）。M2の代理登録通知から |
| コンテナ | Docker（マルチステージ） | |

### 選定方針
**依存ライブラリは最小にする。** このプロジェクトは数年で担当者が全入れ替えする。フレームワークの流行り廃りに乗ると、引き継いだ人が読めなくなる。標準ライブラリで書けるものは標準ライブラリで書く。

`golang.org/x/crypto/bcrypt` はこの方針の例外。**パスワードハッシュは自作してはいけない領域**であり、Go 公式の準標準ライブラリなので許容する。

### 構成
フロントエンドのビルド成果物を Go バイナリに `embed` し、**単一バイナリ + SQLiteファイル**で動く形にする。デプロイと引き継ぎが劇的に楽になる。

## 3. 認証仕様

### 方式：admin 発行の ID + パスワード

マジックリンクは**採用しない**。

**理由：** マジックリンクは SMTP が使えることが動作の前提になる。学内SMTPの可否が未確定な段階でログイン手段をメールに依存させると、SMTP が使えなかった時点でシステム全体が起動できない。パスワード方式はメールに一切依存しないため、SMTP の可否・学外アクセスの可否によらず必ず動く。

当初の「名前選択式では『俺は借りてない』という否認を排除できない」という要件は、個人ごとの認証情報を持つ本方式でも同様に満たされる。

### フロー
1. admin が `/admin/users` でユーザーを作成し、**ログインID と初期パスワードを発行**する
2. 発行された初期パスワードは**作成直後の画面に一度だけ表示**する（DBには平文を残さない）
3. ユーザーは `/login` で ID + パスワードを入力
4. 検証成功 → `sessions` にセッション作成、Cookie 発行
5. `must_change_password = 1` なら**パスワード変更画面へ強制遷移**
6. `next` パラメータがあればそのURLへリダイレクト

### 要件
- パスワードは **bcrypt** でハッシュ化（`golang.org/x/crypto/bcrypt`）。平文保存しない
- **セッション有効期限は1年。** 2回目以降ログイン操作を発生させないことが目的
- Cookie は `HttpOnly`, `SameSite=Lax`, `Secure`
- `is_active = 0` のユーザーはログイン不可
- 存在しないIDと誤ったパスワードで**エラーメッセージを変えない**（ID の存在を推測させない）
- **総当たり対策**：`login_attempts` を用い、同一 login_id への失敗が短時間に一定回数を超えたら遅延または一時ロックする。数十名規模なので凝った実装は不要
- パスワードリセットは admin による再発行のみ。**自己リセット導線を作らない**（メールに依存するため）

### 落とし穴

**`Secure` 属性と HTTP 運用の衝突。** オンプレで HTTPS を用意せず HTTP で公開すると、`Secure` 付き Cookie はブラウザに保存されずログインが無限ループする。`COOKIE_SECURE` 環境変数で切り替え可能にし、**デフォルトは `true`** とする。HTTP で運用する場合のみ明示的に落とす。

**`next` パラメータでの復帰は必ず実装すること。** QRから来た未ログインユーザーを、認証後にトップへ放り出すと、**もう一度QRを読み直させることになる。この一手間が記録漏れの直接原因になる。**
オープンリダイレクトを防ぐため、`next` は自サイト内の相対パスのみ許可する（`/` で始まり `//` で始まらないもののみ）。

### email の扱い

`users.email` は**通知専用で、認証には使わない。NULL を許容する。**

SMTP が使えない環境ではメール未設定のまま運用でき、その場合はメール通知をスキップする。M2 の代理登録通知・M3 の定期通知は、この前提で「送れる人にだけ送る」設計にする。

## 4. 備品マスタ

### 権限
| 操作 | admin | member |
|---|---|---|
| 一覧・検索・詳細 | ○ | ○ |
| 登録・編集・削除 | ○ | ✕ |

member が備品レコードを書き換えられないことが、スプレッドシート共有ではなくシステム化する主目的。**API側で必ず検証する。** UIでボタンを隠すだけでは不十分。

### コード採番
- `0001` 形式の4桁ゼロパディング連番
- **採番はシステムが行う。** 人手で振らせない（抜け・重複が必ず起きる）
- 既存の最大値+1。削除された番号は再利用しない
- 4桁で足りなくなったら5桁へ自然に伸ばす（ゼロパディングは最低4桁の意味）

### 削除
物理削除しない。`condition = '廃棄'` で表現する。**`loans` から参照されるため、削除すると履歴が壊れる。**

## 5. CSVインポート

### 入力形式
`inventory-template.xlsx` の「棚卸し」シートをCSV書き出ししたもの。

| 列 | 必須 | 取り込み仕様 |
|---|---|---|
| 品名 | ○ | `items.name` |
| 分類 | ○ | `items.category`。自由入力をそのまま格納 |
| 数量 | ○ | **この数だけレコードを生成し、それぞれに連番を採番する** |
| 保管場所 | ○ | `items.location` |
| 型番・メーカー | | `items.model` |
| 状態 | | `items.condition`。空欄は `良好` |
| 所有 | | `items.owner`。空欄は `サークル` |
| 自由利用 | | `items.is_free_use`。`TRUE`/`FALSE`、空欄は `0` |
| 備考 | | `items.note` |

### ヘッダ行の注意（テンプレート実物より）

`inventory-template.xlsx` の「棚卸し」シートのヘッダは、必須列に全角スペース＋アスタリスクが付いている。

```
品名　* | 分類　* | 数量　* | 保管場所　* | 型番・メーカー | 状態 | 所有 | 自由利用 | 備考
```

**ヘッダ照合の前に `　*`・空白・BOM を除去して正規化すること。** 素朴に完全一致で判定すると、テンプレートをそのまま書き出したCSVが1件も取り込めない。

また2行目には記入例（`三脚（大）` の行）が入っている。記入ガイドには「作業前に削除する」と書かれているが、**消し忘れは必ず起きる。** プレビュー画面で全行を見せ、ユーザーが除外できるようにする。

### 要件
- **取り込み前にプレビューを出す。** 「何件が何レコードに展開されるか」を表示し、確認後に確定する
- 空行（全列が空）はスキップする。テンプレートは200行の空行を持つため、これを弾かないとエラーが200件出る
- **全件成功か全件失敗か（トランザクション）。** 途中まで取り込まれた状態は、やり直しの判断がつかなくなる
- エラーは**行番号と理由を全件まとめて返す**。1件ずつ直させない
- 文字コードは UTF-8 と Shift_JIS の両方を受け付ける（Excel からの書き出しで後者になりがち）
- BOM を除去する

## 6. QR / ラベル印刷

### QRの内容
`https://{host}/i/{code}` のみ。ホスト名は環境変数。

### ラベルPDF
- 想定用紙: **A4 24面（70 × 33.9mm）のラベルシール**
- 1ラベルの内容: QRコード + コード（`0042`）+ 品名
- 印刷対象を範囲指定できること（コード範囲、分類、未印刷のみ など）
- 印刷済みフラグは持たなくてよい（範囲指定で足りる）

### 落とし穴
**PDFに日本語フォントを埋め込む必要がある。** 品名を印字するため。Noto Sans JP 等の TTF をバイナリに `embed` して `fpdf` に登録すること。これを忘れると品名が全て文字化けするか空白になる。Docker イメージにフォントを入れる方式は、イメージ差し替えで壊れるので避ける。

QRの誤り訂正レベルは **M**。汚れる環境なので L は避ける。ただし H にするとセルが細かくなり、70mm幅のラベルでは読みにくくなる。

## 7. 画面

`url-design.md` の一覧のうち、M1で実装するもの:

| URL | 内容 |
|---|---|
| `/login` | ログイン（ID + パスワード） |
| `/password` | パスワード変更（初回ログイン時は強制遷移） |
| `/` | トップ（M1では備品一覧へのリンクのみ） |
| `/items` | 備品一覧・検索（分類・保管場所・状態でフィルタ） |
| `/i/{code}` | 備品詳細（M1では表示のみ。貸出ボタンは出さない） |
| `/admin/items` | 備品マスタ管理 |
| `/admin/items/new` | 登録フォーム |
| `/admin/items/import` | CSVインポート |
| `/admin/labels` | ラベル印刷 |
| `/admin/users` | ユーザー管理 |

### UI方針
**モバイルファースト。** デスクトップ対応ではなく、スマホを前提に設計してレスポンシブで広げる。実際の利用の大半はスマホ。

## 8. 非機能

- **CSVエクスポートを実装する。** システムが死んでもデータは残る。これは初期リリースに必ず含める
- 設定は全て環境変数（`HOST_URL`, `DB_PATH`, `SESSION_SECRET`, `COOKIE_SECURE`, `UPLOAD_DIR`。`SMTP_*` は M2 から）
- **初期 admin の作成手段を用意する。** ユーザーは admin しか作れないため、最初の1人を作る導線がないと誰もログインできない。`./server -create-admin` のようなサブコマンドで作る（Web からは作れないようにする）
- 写真は DB ではなくファイルシステムに保存し、パスを `items.photo_path` に持つ
- ログは標準出力（Docker のログ収集に任せる）
- バックアップ手順を README に書く（SQLite はファイルコピーで完結するが、**WALモードなので `.backup` コマンドか、書き込み停止中のコピーを使う**）

## 9. 受け入れ条件

- [ ] `-create-admin` で最初の admin を作成でき、そのIDでログインできる
- [ ] admin がユーザーを登録すると初期パスワードが一度だけ表示され、そのIDでログインできる
- [ ] 初回ログイン時にパスワード変更が強制される
- [ ] 存在しないIDと誤ったパスワードで、エラーメッセージが区別できない
- [ ] `is_active = 0` のユーザーがログインできない
- [ ] member が備品を編集しようとすると、API レベルで拒否される
- [ ] 棚卸しCSVを取り込むと、数量分のレコードが連番付きで生成される
- [ ] `品名　*` 形式のヘッダを持つテンプレート書き出しCSVが、そのまま取り込める
- [ ] 取り込みエラー時、1件も登録されていない
- [ ] ラベルPDFを印刷すると、日本語の品名が正しく表示される
- [ ] 印刷したQRをスマホの標準カメラで読むと、備品詳細に遷移する
- [ ] 未ログインでQRを読むと、認証後に元の備品詳細へ戻る
- [ ] `next=https://evil.example.com` のような外部URLへリダイレクトしない
- [ ] 全備品をCSVでエクスポートできる
