# M4 実装依頼書：公開API・サイネージ連携

> **必ず最後に実装すること。** データ構造が固まる前に API を公開すると、サイネージ側を壊さずに変更できなくなる。M1〜M3 の運用でスキーマが安定してから着手する。

## 0. スコープ

- read only の公開API（トークン認証）
- サークルのイベント管理サイネージへの表示連携

書き込みAPIは実装しない。

---

## 1. サイネージの表示方針（設計の核心）

### 平常時は件数のみ、期限超過のみ実名

| 状態 | 表示 |
|---|---|
| 通常の貸出中 | **件数のみ**（「貸出中 12件」） |
| 期限超過 | **備品名と借用者名を実名で表示** |
| 所在不明 | 備品名を表示（報告者名は出さない） |

### この設計の理由

サイネージの目的は、**アプリを開かない層にも状況を届けること**。「貸出中12件」とだけ表示しても誰の行動も変わらないため、完全な匿名化では設置する意味がほぼ消える。

一方、部室には学科の教員や他の学生も出入りするため、常時実名を掲示するのは抵抗がある。これは正当な懸念。

**期限超過のみ実名にすることで両立する：**
- 名前が出るのは「期限を過ぎている」という明確な逸脱時だけなので、晒し上げ感が薄い
- 抑止力は最大（名前を出したくなければ期限内に返せばよい）
- 平常時は個人名が並ばず、外部の目にも不自然でない
- 平常時の実名による可視性は、アプリ内の `/loans` で確保する

## 2. エンドポイント

すべて `GET`、read only。

### `GET /api/v1/summary`
サイネージのメイン表示用。1リクエストで必要な情報が揃うようにする。

```json
{
  "total_items": 342,
  "active_loans": 12,
  "overdue": [
    { "item_code": "0042", "item_name": "三脚（大）", "borrower_name": "山田太郎", "days_overdue": 3 }
  ],
  "missing": [
    { "item_code": "0117", "item_name": "HDMIケーブル 5m", "status": "確定" }
  ],
  "generated_at": "2026-09-01T09:00:00+09:00"
}
```

**サイネージが複数エンドポイントを叩かなくて済む形にする。** 表示に必要な単位でまとめるのが、この API の設計方針。

### `GET /api/v1/items`
備品一覧。`category`, `location`, `condition` でフィルタ可能。個人情報を含まない。

### `GET /api/v1/loans/active`
貸出中一覧。**借用者名を含めない**（件数と備品名のみ）。実名が必要な場合は `/summary` の `overdue` を使う。

### `GET /api/v1/items/missing`
所在不明一覧。報告者名は含めない。

## 3. 認証・仕様

- `Authorization: Bearer {token}`。`api_tokens` テーブルで検証（ハッシュ照合）
- `scope` は `read` のみ
- **パスにバージョンを含める**（`/api/v1/`）。サイネージ側を後から壊さないため
- レスポンスは JSON、`Content-Type: application/json; charset=utf-8`
- 日時は ISO 8601（タイムゾーン付き）
- `api_tokens.last_used_at` を更新し、使われていないトークンを検出できるようにする

### CORS
サイネージがブラウザベースなら、そのオリジンのみ許可する。ワイルドカードにしない。

### キャッシュ・ポーリング
- サイネージ側のポーリングは **1〜5分間隔**を推奨。秒単位で更新する必要はない
- サーバ側は 60 秒程度のキャッシュで十分
- `Cache-Control` を明示する

---

## 4. 実装上の注意

### ビューをそのまま返さない
`v_overdue_loans` などのビューはあくまで内部表現。**API のレスポンス構造は独立して定義し、DTO を介して変換する。** スキーマ変更が即 API の破壊にならないようにするため。これが M4 を最後に置く意味そのもの。

### 個人情報の混入を防ぐ
`overdue` 以外のレスポンスに `borrower_name` や `reporter_id` を含めないこと。**テストで明示的に検証する。** 一度サイネージに出た情報は取り消せない。

## 5. 受け入れ条件

- [ ] トークンなしでアクセスすると 401 が返る
- [ ] 無効化されたトークンで 401 が返る
- [ ] `/summary` の `overdue` にのみ借用者名が含まれる
- [ ] `/loans/active` と `/items/missing` に個人名が一切含まれない（テストで検証）
- [ ] サイネージ側が1リクエストで必要な情報を取得できる
- [ ] 60秒キャッシュが効いている
- [ ] `api_tokens.last_used_at` が更新される
