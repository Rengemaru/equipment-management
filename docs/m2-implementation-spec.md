# M2 実装依頼書：貸出・返却

## 0. 前提

M1（認証・備品マスタ・QR発行）が完了していること。
**M2 の完了条件は「QRを読んでから3タップ以内で借用が完了すること」。** 機能が揃っていても、この操作量を超えたら M2 は未完了とみなす。

---

## 1. スコープ

### 実装する
- 借用登録（QRから、代理登録、事後登録）
- 返却登録
- 破損報告（任意ボタン）
- 貸出中一覧（全員に公開）
- 自分の貸出中・履歴

### 実装しない（M3以降）
定期通知、所在不明報告、棚卸しモード。
ただし**代理登録の本人通知メールだけは M2 に含める**（M1 で SMTP 基盤ができているため、ここで送れる）。

---

## 2. 借用フロー（最重要）

### 操作の想定
1. QRをOS標準カメラで読む → `/i/0042` に遷移（**ここまで操作ゼロ**）
2. 画面に「借りる」ボタン → タップ
3. 確認 → 完了

**返却予定日は借用日+14日を最初から入れておき、変更したい人だけ変える。** 日付入力を必須にしない。ここが摩擦の最大の発生源になる。

### 備品詳細画面（`/i/{code}`）の表示分岐

| 備品の状態 | 表示 |
|---|---|
| 貸出可能 | 「借りる」ボタン（主要導線として大きく） |
| 貸出中（他人） | 借用者名・返却予定日・「破損を報告」 |
| 貸出中（自分） | 「返す」ボタン・「破損を報告」 |
| 自由利用品 | 情報表示のみ。**貸出ボタンを出さない** |
| `condition = 廃棄` | 貸出不可を明示 |
| `location_status = 所在不明_*` | 「借りる」は出すが警告を表示（下記） |

### 必須：借用画面に現在の状態と備考を表示する

「状態：良好 / 備考：脚のロックが緩い」を借りる前に見せる。

破損報告は任意ボタンなので、**報告されないまま次の人が借りるケースが必ず出る。** そのとき現状表示がないと、前の人の破損が次の人の責任になる。次に借りる人が食い違いに気づけば、その場で報告できる。実装は軽く、責任の誤帰属を防ぐ効果は大きい。

### 所在不明の備品が見つかった場合の自動処理

`location_status` が `所在不明_未確認` / `所在不明_確定` の備品に対して借用が成立したら：
- `location_status` を `在庫` に戻す
- 該当する `missing_reports` を `発見済み` に更新する

**見つかったという事実は、借りた人が報告するのではなく、借用操作から自動で導く。** 追加操作を求めない。

---

## 3. 代理登録

「〇〇さんが持っていくのを見た」を第三者が登録できる。

- 借用画面で借用者を自分以外から選択できる
- `loans.user_id` = 借用者、`loans.registered_by` = 登録者
- **借用者本人にメール通知する**（「あなたの名前で借用が登録されました」＋訂正リンク）
- 本人が訂正できる導線を必ず設ける（誤登録の可能性があるため）

これは「本人が記録しなくても穴が埋まる」ための仕組み。記録漏れ対策の中核なので、導線を深い階層に埋めないこと。

---

## 4. 事後登録

持ち出した後に自宅からでも登録できる。

- 借用画面は同一。`borrowed_at` を過去日時に変更できるようにする（デフォルトは現在時刻）
- **「もう持ち出しちゃったから今さら」を潰すことが目的。** トップから1タップで到達できる位置に導線を置く

---

## 5. 返却

- `/i/{code}/return` または一覧からのボタン
- **借用者本人以外も返却登録できる。** 棚に戻っているのを見つけた人が処理できないと、記録が永久にズレたままになる。`loans.returned_by` に実行者を記録する
- 返却時に確認ダイアログを出さない（摩擦低減。誤返却は再度借りれば済む）

### 設計上の非対称性
**借用の記録漏れは致命的（誰が持っているか永久に不明）、返却の記録漏れは自己修復する（本人に聞けば解決）。** UIの作り込みは借用側に厚く、返却側は薄くてよい。

---

## 6. 破損報告

- 「破損を報告」ボタンを備品詳細に常設（貸出中・在庫中どちらでも押せる）
- 入力：破損箇所の説明（必須）、写真（任意）
- `damage_reports` に記録。貸出中に報告された場合は `loan_id` を紐付ける
- **報告と同時に `items.condition` を `要修理` に変更する。** 承認を待たない（所在不明報告と同じ思想）
- 運営は `/admin/damages` で追認し、`確認済み` / `修理済み` / `廃棄` に更新する

---

## 7. 一覧画面

### `/loans` 貸出中一覧（全メンバーに公開）
- 備品名・借用者名・返却予定日・超過日数
- 期限超過を視覚的に区別する
- **誰が何を持っているかが全員に見える状態を作ることが目的。** 可視性は罰則より強く働く

### `/loans/mine` 自分の貸出
- 貸出中と過去の履歴
- 各行から返却できる

---

## 8. データ整合性

- 同一備品の二重貸出は `loans` の部分ユニークインデックスが DB レベルで拒否する。**アプリ側でもハンドリングし、「他の人が先に借りました」と表示する**（500 を返さない）
- 返却しても `loans` の行を削除しない
- `is_free_use = 1` の備品に対する借用APIは 400 で拒否する（UIで隠すだけにしない）

---

## 9. 受け入れ条件

- [ ] QRを読んでから借用完了まで3タップ以内
- [ ] 返却予定日が最初から入力されており、触らずに借用できる
- [ ] 未ログイン状態でQRを読み、認証後に元の備品ページへ戻って借用できる
- [ ] 代理登録すると、借用者本人にメールが届く
- [ ] 同一備品を2人が同時に借りようとすると、後者にエラーが表示される（500 にならない）
- [ ] 借用者以外が返却登録でき、`returned_by` に記録される
- [ ] 所在不明の備品を借用すると、自動で在庫に戻り報告が発見済みになる
- [ ] 借用画面に現在の状態と備考が表示される
- [ ] 自由利用品には借用ボタンが出ず、API も拒否する
