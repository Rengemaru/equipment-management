# URL設計

## 1. QRに埋め込むURL（最重要・後から変更不可）

```
https://{host}/i/{code}
例: https://binmgr.example.ac.jp/i/0042
```

### `/i/` にした理由
- **短いほどQRのセル数が減り、小さいラベルでも読める。** 本の背表紙や機器の隙間に貼ることを考えると、これは実用上の差になる
- パス名に意味（`/items/`, `/books/`）を持たせない。ラベルは貼り替えられないため、命名の変更余地を残さない
- ホスト名も短いものを選ぶこと。ここが長いとラベルサイズに直結する

### 遷移仕様
| 状態 | 挙動 |
|---|---|
| ログイン済み・貸出可能 | 備品詳細を表示、「借りる」ボタンが即座に押せる状態 |
| ログイン済み・貸出中 | 誰が借りているかを表示、自分が借りていれば「返す」ボタン |
| ログイン済み・自由利用品 | 情報表示のみ（貸出ボタンを出さない） |
| 未ログイン | `/login?next=/i/0042` へ。認証後に**必ず元のページへ戻す** |

`next` パラメータでの復帰は必須。ここで戻さないとトップに放り出され、もう一度QRを読む羽目になる。**この一手間が記録漏れの直接原因になる。**

---

## 2. 出口・棚に貼る動線QR

```
https://{host}/
```

トップに「貸出中一覧」「自分が借りているもの」「所在不明を報告」を置く。個別備品ではなく**部屋を出るときに目に入る位置**に貼る。

---

## 3. 画面URL一覧

### メンバー
| URL | 画面 |
|---|---|
| `/` | トップ（自分の貸出中・全体の貸出中一覧） |
| `/i/{code}` | 備品詳細（QRの遷移先） |
| `/items` | 備品一覧・検索 |
| `/loans` | 貸出中一覧（全員分） |
| `/loans/mine` | 自分の貸出中・履歴 |
| `/i/{code}/borrow` | 借用登録（代理登録・事後登録もここ） |
| `/i/{code}/return` | 返却登録 |
| `/i/{code}/report-missing` | 所在不明報告 |
| `/login` | マジックリンク送信 |
| `/auth/{token}` | メールのリンク先（セッション発行 → `next` へ） |

### 運営
| URL | 画面 |
|---|---|
| `/admin/items` | 備品マスタ管理 |
| `/admin/items/new` | 備品登録（スマホ・写真添付） |
| `/admin/items/import` | CSV一括インポート |
| `/admin/labels` | QRラベル一括印刷（PDF出力・範囲指定） |
| `/admin/missing` | 所在不明報告の追認 |
| `/admin/inventory` | 棚卸し（連続スキャンモード） |
| `/admin/users` | ユーザー管理 |
| `/admin/tokens` | APIトークン管理 |

## 4. 公開API（M4・read only）

```
GET /api/v1/items
GET /api/v1/loans/active
GET /api/v1/items/missing
```

- 認証: `Authorization: Bearer {token}`（`api_tokens` テーブル）
- バージョンを最初からパスに入れる。サイネージ側を後から壊さないため
- **M4は必ず最後に実装する。** データ構造が固まる前に公開すると変更できなくなる

---

## 5. 決定事項の要点

- 備品コードは `0001` 形式の4桁ゼロパディング連番。**分類の意味を持たせない**
- ラベルには「`0042` / 三脚（大）」のようにコードと品名を併記する。分類を読み取りたい欲求はここで満たす
- コードは棚卸しシートには記入しない。**インポート時にシステムが自動採番する**
